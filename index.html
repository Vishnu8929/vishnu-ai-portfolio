03 / Projects

Systems, not demos.

Two personal projects, each built end to end. They show how I design AI systems when I own every layer.

Personal project

Production Agentic RAG Knowledge Assistant

An agentic RAG service that decides which sources a question needs (documents, vector search, a database, or an external API) before generating a grounded, validated answer.

Problem

Enterprise questions rarely live in one place. Some need passages from documents, some need structured records, some need a live API. A single vector search over everything returns plausible but incomplete context.

Key decisions

  1. Route by intent. A LangGraph agent decides which tools to call, over one or more steps, instead of retrieving from every source for every question.
  2. Separate the layers. Ingestion, orchestration, retrieval, generation, and the FastAPI service are independent components, so each can change without rewriting the others.
  3. Validate before responding. Model outputs and tool responses go through structured validation and explicit handling instead of being passed straight to the user.

Production considerations

  • Retrieval depth and context size tuned against answer quality, latency, token usage, and API cost.
  • Ingestion pipeline for preprocessing, chunking, embedding generation, and vector indexing.
  • Containerized with Docker and deployed on AWS for reproducible environments.

StackPython · FastAPI · LangGraph · Embeddings · FAISS · Docker · AWS

Personal project

Real-Time AI Voice Agent

A phone-based voice agent that streams live call audio to a speech-to-speech model and back, with recordings and transcripts captured for evaluation.

Problem

A phone conversation can't be built as request and response. Audio has to flow both ways continuously, with low enough latency that the conversation doesn't stall.

Key decisions

  1. Persistent WebSocket bridge. A FastAPI service manages real-time audio between Twilio Media Streams and the OpenAI Realtime API over persistent WebSocket connections.
  2. Scenario-driven behavior. Personas and system prompts are defined per scenario, so one pipeline can run many test conversations.
  3. Capture everything. Call audio and timestamped transcript events are preserved for evaluation and debugging.

Production considerations

  • Designed for low-latency bidirectional audio streaming and real-time conversational interaction.
  • Telephony, API, LLM orchestration, scenarios, and transcript processing are separate modules that can be extended independently.

StackPython · FastAPI · Twilio Media Streams · WebSockets · OpenAI Realtime API

04 / Engineering

How I think about production AI.

  1. 01

    Ground the model

    Answer quality is mostly decided before generation: what gets retrieved, how much context is passed, and whether it's the right context.

    Seen in: retrieval grounding at PathAI · tool routing in the Agentic RAG project

  2. 02

    Evaluate everything

    Reading a few outputs isn't evaluation. Quality needs repeatable checks for factual consistency, schema validity, formatting, and regressions.

    Seen in: LLM evaluation pipelines at PathAI · regression testing at Cognizant

  3. 03

    Design for failure

    Models, retrieval, tools, APIs, and databases each fail differently. Validate at the boundaries and make failures traceable.

    Seen in: incident root cause analysis at Cognizant · structured validation in the Agentic RAG project

  4. 04

    Optimize the whole system

    Quality has to be balanced against latency, context size, token usage, reliability, and cost, tuned together rather than one at a time.

    Seen in: token and latency tuning at PathAI · retrieval depth and context size in the Agentic RAG project
